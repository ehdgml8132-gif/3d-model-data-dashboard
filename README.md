# Monospace · 3D 모형 데이터 대시보드

3D 공간의 객체를 클릭해 관련 데이터를 살펴보는 React 웹 앱입니다. **카페 판매 대시보드**와 **건물·IFC 부재 대시보드**를 제공합니다. 기존 카페·3층 건물 샘플을 유지하면서, 실제 IFC를 열고 엑셀·CSV의 업무 정보를 부재에 연결할 수 있습니다. 파일은 브라우저에서 처리하며 서버로 업로드하지 않습니다.

## 실행

Node.js 24 LTS와 npm을 사용합니다. 이 저장소의 기존 체크아웃에서 실행하세요.

```bash
npm ci
npm run dev
```

개발 서버 기본 포트는 `5173`입니다. 프로덕션 빌드는 `npm run build`, 빌드 결과 로컬 확인은 `npm run preview`입니다.

## 웹사이트 배포

이 앱은 별도 서버나 서버 DB 없이 정적 웹사이트로 게시할 수 있습니다. 프로젝트는 사용 중인 브라우저의 IndexedDB에 저장합니다. 카페와 건물, 공간·부재 데이터 화면이 하나의 사이트에 포함됩니다. 빌드의 상대 경로를 사용하므로 도메인 루트와 GitHub Pages의 저장소 하위 경로에서 모두 사용할 수 있습니다.

GitHub Pages 자동 배포 설정은 `.github/workflows/deploy-pages.yml`에 있습니다. GitHub 저장소 **Settings → Pages → Build and deployment → Source**에서 **GitHub Actions**를 선택하면, `main`에 코드를 올리거나 **Actions → Deploy Monospace website → Run workflow**로 빌드·배포할 수 있습니다. 워크플로가 표시하는 실제 배포 URL을 확인하세요. 로컬 설정 파일이 추가된 것만으로 원격 사이트가 게시되지는 않습니다.

정적 호스팅에 직접 업로드할 ZIP은 다음 명령으로 생성합니다.

```bash
npm run build:site
```

`dist/monospace-website.zip`을 풀면 `index.html`, `assets/`, `ifc/`, `examples/`, `favicon.svg`, `sample-products.csv`, `THIRD_PARTY.md`와 HTML 내보내기용 `monospace-building-preview.html`이 들어 있습니다. IFC 엔진이 들어 있는 **`ifc/` 폴더를 포함해 전체 내용**을 정적 호스팅의 게시 폴더에 올리세요. 빌드 명령은 `npm run build`, 게시 폴더는 `dist`입니다. Node.js 서버를 계속 실행할 필요는 없습니다.

ZIP 생성 명령에는 Python 3가 필요합니다. 일반 웹사이트 빌드와 GitHub Pages 배포에는 Python을 직접 실행하지 않습니다.

사이트 첫 화면은 카페입니다. 같은 사이트 주소 뒤에 `?sample=building`을 붙이면 건물 샘플로 시작합니다. 업로드한 카페 CSV는 사용 중인 브라우저에만 저장되며 사이트 방문자 사이에서 공유되지 않습니다.

### 서버 없이 화면 열기

이 클라우드 채팅에서는 실행 중인 개발 서버가 자동으로 웹 미리보기로 표시되지 않습니다. 별도의 호스팅 없이 화면을 확인하려면 다음 명령으로 단일 HTML 파일을 만들 수 있습니다.

```bash
npm run build:standalone
```

생성된 `dist/monospace-preview.html`을 내려받아 Chrome·Edge 등 WebGL 지원 브라우저에서 여세요. 파일 안에 JavaScript·스타일·샘플 CSV가 포함되어 있어 서버나 패키지 설치 없이 3D 상품 선택, 차트, CSV 업로드를 사용할 수 있습니다. 이 파일은 오프라인 확인용이며 공개 웹 주소를 생성하거나 배포하지 않습니다. 코드 변경 후에는 다시 생성해야 합니다.

건물 샘플로 바로 시작하는 `dist/monospace-building-preview.html`도 함께 생성합니다. 두 파일 모두 사이드바의 **카페 샘플 / 건물 샘플** 버튼으로 예제를 바꿀 수 있습니다. 기존 카페에서 업로드한 데이터는 샘플을 전환해도 유지됩니다.

## 건물 모델 샘플

기존 카페와 별도로, 코드로 만든 **3층 건물의 BIM 예제**를 제공합니다. 사이드바에서 **건물 샘플**을 누르거나 개발 서버의 `?sample=building`으로 진입할 수 있습니다.

- 전체 또는 특정 층의 기둥·보·슬래브·벽 표시
- 3D 부재 또는 목록 선택 시 부재명·분류·층·재료·규격·체적 표시
- 층·부재 종류·검색 조건에 맞는 목록과 물량 집계
- 화면 회전·확대 및 시점 초기화

건물 메뉴는 **공간 데이터**와 **부재 데이터**로 나뉩니다. 공간 데이터에서 3D 모델·선택한 부재 속성과 층별 물량을 보고, 부재 데이터에서 전체 목록을 검색·필터링하며 재료·IFC 분류·규격·체적을 비교할 수 있습니다. 데이터 목록의 부재를 선택하면 공간 화면으로 이동해 같은 부재를 강조합니다.

층 선택은 두 화면에서 공유합니다. 부재 데이터 화면의 검색어·종류 필터는 그 화면에만 적용되며, 공간 화면의 모델을 숨기지 않습니다. 화면을 오갈 때 검색 조건과 선택한 부재가 유지됩니다.

### 카드 필터

뷰어 위 요약 카드 네 개의 우측 상단 아이콘을 누르면 필터가 열립니다. **표시 부재**는 부재 종류나 개별 부재, **총 체적**은 m³ 범위와 체적 미확인 포함 여부, **표시 층**과 **재료 종류·표기**는 여러 층이나 재료를 체크해 선택할 수 있습니다. 같은 항목에서 고른 값은 함께 포함하고, 서로 다른 카드의 조건은 모두 만족하는 부재만 표시합니다. 부재 종류와 개별 부재를 함께 지정하면 두 조건을 모두 적용합니다.

카드 필터는 3D 모델·부재 목록·요약 지표·그래프에 함께 적용됩니다. 필터에 가려진 부재의 선택은 해제되며, 조건에 맞는 부재가 없어도 필터의 전체 선택지는 유지됩니다. 각 팝업의 **이 필터 초기화**로 해당 조건을 복원하거나 **전체 필터 초기화**로 모든 조건을 해제할 수 있습니다. 체적 범위는 양 끝 값을 포함하며, 알 수 없는 체적을 0으로 간주하지 않습니다. 목록 체크는 바로 반영되고 체적 범위는 **적용**을 눌러 반영합니다.

필터는 같은 작업 공간에서 화면을 오갈 때 유지됩니다. 새 IFC 모델을 성공적으로 불러오거나 샘플로 돌아가면 초기화되며, 가져오기를 취소하거나 실패하면 기존 조건을 유지합니다. 단면상자는 화면만 잘라 표시하므로 카드 필터의 집계 값을 다시 계산하지 않습니다.

### 선택 해제·단면상자와 그래프

- 처음 건물 화면을 열거나 새 IFC 모델을 불러오거나 샘플로 돌아오면 **객체가 선택되지 않은 상태**로 시작합니다. 이후 직접 선택한 부재는 같은 작업 공간의 화면을 오갈 때 유지됩니다.
- 뷰어의 **빈 곳을 클릭하거나 Esc·선택 해제**를 누르면 부재 강조와 상세 선택을 해제합니다. 단면상자의 화살표도 함께 숨기며 잘린 범위는 유지합니다. 화면이나 층을 바꿔도 다른 부재를 자동으로 선택하지 않으며, 모델이나 목록에서 부재를 다시 선택할 수 있습니다.
- 뷰어 우측 상단 시점 초기화 버튼 옆의 **단면상자**를 켜면 먼저 상자의 윤곽선만 표시됩니다. **윤곽선을 클릭하거나 터치해 상자를 선택하면** 여섯 면을 조절하는 화살표가 나타납니다. 부재가 선택되어 있으면 그 부재를 감싸는 범위로, 선택이 없으면 전체 건물을 포함하는 범위로 시작합니다. 기준은 켜는 순간 정해지므로 이후 다른 부재를 선택하거나 선택을 해제해도 바뀌지 않습니다. 다른 부재나 전체 건물을 기준으로 다시 만들려면 체크를 껐다 켜세요.
- 선택한 단면상자의 **화살표를 직접 드래그**해 좌우·상하·앞뒤 범위를 조절합니다. 화살표를 움직이는 동안에는 화면 회전이 잠시 멈추고, 놓으면 다시 회전할 수 있습니다. 다른 부재를 클릭하면 그 부재를 선택하고 단면상자의 화살표를 숨깁니다. 빈 곳을 클릭하거나 **Esc·선택 해제**를 누르면 객체와 상자 선택을 모두 해제하며 잘린 범위는 유지합니다. 뷰어 상단의 **단면 범위 초기화**는 현재 기준 상자의 여섯 면을 원래 위치로 복원하며, 단면상자 체크를 끄면 전체 형상을 다시 표시합니다. 아래쪽 X·Y·Z 슬라이더는 제공하지 않습니다. 잘린 바깥쪽 부재는 뷰어에서 클릭되지 않습니다.
- 뷰어 아래 **층별 체적/부재 수**와 **부재 종류 구성** 그래프는 현재 층 필터의 데이터를 보여줍니다. 단면상자는 표시만 자르므로 표·그래프의 부재 개수와 체적을 재계산하지 않습니다. IFC 체적은 계속 Pset의 `체적`/`Volume` 값을 사용하며, 체적이 없는 부재는 0으로 확정하지 않고 미확인 수를 표시합니다. 층별 그래프의 수치는 **층별 수치 보기**에서도 확인할 수 있습니다.

기본 3층 샘플은 Revit에서 내보낸 파일을 읽은 결과가 아닙니다. `IfcColumn` 등의 분류와 `DEMO-`로 시작하는 ID는 데이터 연결 방식을 보여주기 위한 가상 값입니다. 샘플 체적은 직육면체 형상의 단순 합계이며, 부재 접합부 중복을 차감하지 않습니다. **IFC 모델 업로드**를 누르면 이 샘플 대신 사용자의 실제 모델을 표시하고 **샘플로 돌아가기**로 복원할 수 있습니다.

## 실제 IFC 모델과 업무 데이터 연결

1. **건물 샘플 → IFC 모델 업로드**에서 Revit 등에서 내보낸 `.ifc`를 선택합니다.
2. 가져오기가 끝나면 실제 삼각형 형상이 표시됩니다. 부재를 누르면 GlobalId·Tag·IFC 분류·층·재료와 지원되는 속성집합(Pset), 수량집합(Qset), 유형 속성을 확인할 수 있습니다.
3. **공간 데이터 / 부재 데이터**에서 층과 종류를 선택하고 실제 부재 목록을 검색합니다. IFC의 층 이름을 그대로 사용하며, 층 관계가 없는 부재는 미지정으로 표시합니다.
4. **업무 데이터 연결**에서 `.csv` 또는 `.xlsx`를 선택합니다. 엑셀은 읽을 시트를 선택하세요. 각 시트의 첫 번째 비어 있지 않은 행을 열 이름으로 사용합니다.
5. 모델 연결 키 **GlobalId / Tag / 부재 ID**와 데이터의 대응 열을 지정합니다. 연결 가능·미연결·중복 진단을 확인하고 **데이터 연결**을 누릅니다.
6. 부재를 클릭하면 연결된 공사비·진행 상태·담당자 등 파일에 들어 있는 열을 속성 카드에서 확인할 수 있습니다. **업무 데이터 연결 해제**는 모델을 유지한 채 표 연결만 제거합니다.

연결키는 앞뒤 공백을 제거한 **문자열의 정확한 값**으로 비교합니다. 대소문자와 선행 0을 구분합니다. 엑셀 ID 열은 텍스트로 저장하는 것을 권장합니다. GlobalId는 내보낸 IFC의 값을 사용하고, 내부 번호 기반 `IFC-번호`는 개정 모델 간 고정 식별자로 간주하지 마세요. 같은 키에 여러 행·부재가 있으면 모호한 후보를 표시하며 임의의 첫 행을 연결하거나 물량을 합산하지 않습니다.

업무 파일은 카페 CSV와 다른 일반 표 형식이며 `P001~P004` 제약이 없습니다. 연결된 값을 표시하는 기능으로, 임의 업무 열의 집계 차트·공사비 계산·공정 자동 판정은 아직 제공하지 않습니다. XLSX 수식은 실행하지 않고 저장된 계산 결과만 읽습니다. 결과가 없는 수식은 빈 값으로 표시합니다.

### 모델 수량·단위와 처리 한도

- IFC 형상은 공식 **web-ifc 0.0.78** 엔진으로 해석하고 실제 배치 행렬을 적용합니다. 원본 길이 단위와 뷰어의 미터 좌표를 구분합니다.
- 체적은 속성집합(Pset)의 단일 속성인 **`체적`(Revit) 또는 `Volume`**에서 읽습니다. 속성의 명시적 단위, 프로젝트의 체적 단위 또는 값에 표시된 지원 단위 접미사를 사용해 m³로 정규화합니다. **속성값이나 단위를 알 수 없으면 `—`**로 표시합니다. Qto/BaseQuantities·형상·경계상자 값으로 대체하지 않습니다. 합계에는 변환된 체적만 포함하고 누락 수를 안내합니다. Qset은 부재의 일반 속성 조회에서 계속 확인할 수 있습니다.
- 일부 속성·단위를 지원하지 못하면 가져오기 안내를 확인하세요. 속성 조회·체적 속성 표시는 설계 검증이나 정밀 물량 산출을 대체하지 않습니다.
- IFC: 최대 **150MB**, 부재 50,000개, 배치 메시 100,000개, 복사한 형상 버퍼 240MB. 한도를 넘으면 모델을 분할해 내보내세요. 모델 복잡도와 기기 메모리에 따라 더 작은 파일에서도 한도가 적용될 수 있습니다.
- 업무 CSV/XLSX: 최대 **10MB**, 시트 30개, 시트당 데이터 30,000행·200열·1,000,000셀. XLSX는 압축 해제 항목·전체 크기도 검사합니다. `.xls`, `.xlsm`, 암호화 파일은 지원하지 않습니다. CSV는 UTF-8로 저장하세요.

불러오기는 별도 작업자에서 수행하며 취소할 수 있습니다. 가져오기에 실패하거나 취소하면 기존 모델·업무 연결을 유지합니다. **새 모델을 성공적으로 불러오면 이전 업무 연결은 해제**하므로 새 모델의 키에 맞게 다시 연결하세요.

저장하지 않은 IFC 모델과 업무 표는 현재 페이지에서만 유지됩니다. 새로고침·탭 종료 뒤 다시 열려면 아래 프로젝트 저장 기능을 사용하세요. 카페 판매 CSV의 기존 브라우저 저장 기능은 그대로입니다.

### 프로젝트 저장·다른 이름으로 저장

1. IFC 모델을 업로드하고 업무 표 연결과 화면 설정을 마친 뒤 **프로젝트 저장**을 누르고 이름을 입력합니다. 원본 IFC 파일, 연결한 업무 표·연결 키와 현재 화면을 이 브라우저에 저장합니다.
2. 이후 **프로젝트 저장**은 현재 저장본을 갱신합니다. **다른 이름으로 저장**은 새 프로젝트를 만들므로 이전 저장본을 유지하면서 현장·작업별 사본을 만들 수 있습니다. 같은 이름을 입력해도 다른 이름으로 저장은 기존 항목을 덮어쓰지 않습니다.
3. 새로고침하거나 탭을 다시 연 뒤 **프로젝트 열기**에서 저장한 항목을 고릅니다. 원본 IFC를 다시 해석하고 업무 표를 연결한 뒤 공간/부재 화면, 카드 필터, 검색·종류 조건, 선택한 부재, 단면상자, 시점을 복원합니다. 열기에 실패하거나 취소하면 현재 모델과 화면은 유지합니다.
4. **파일로 내보내기**는 원본 IFC와 업무 표·화면 설정, 뷰어를 포함하는 **`.html` 파일**을 내려받습니다. 파일을 Chrome·Edge 등에서 직접 열면 저장한 프로젝트가 복원되며, 인터넷 연결이나 별도 서버 없이 모델·데이터를 살펴볼 수 있습니다. 다른 기기로 전달할 때도 HTML 파일 하나만 복사하면 됩니다. HTML 안에서 수정한 화면도 다시 **파일로 내보내기**할 수 있습니다.
5. 사이트의 **프로젝트 열기 → 프로젝트 파일 열기**에서도 내보낸 HTML을 가져올 수 있습니다. 이전 `.monospace` 파일도 계속 읽을 수 있습니다. 파일을 연 것만으로 브라우저 저장 목록에 추가되지는 않으므로 계속 보관하려면 **프로젝트 저장**을 누릅니다.

프로젝트는 **직접 저장할 때의 상태**를 보관하며 자동 저장하지 않습니다. 브라우저 저장본은 같은 사이트 주소·같은 브라우저에서만 열 수 있고 계정·서버 동기화·사용자 간 자동 공유는 없습니다. 브라우저 데이터 삭제나 비공개 모드 종료로 사라질 수 있으므로 보관·전달할 자료는 프로젝트 파일로도 내보내세요. 저장소가 차단되거나 용량이 부족하면 오류를 표시하고 기존 저장본을 유지하며, 파일 내보내기는 계속 사용할 수 있습니다.

프로젝트는 원본 IFC 최대 **150MB**, 설정과 업무 표를 담는 프로젝트 메타데이터 최대 **64MB**를 지원합니다. HTML에는 뷰어와 IFC 처리 엔진도 포함되므로 원본 IFC보다 파일이 커집니다. 브라우저에 저장할 수 있는 전체 용량은 기기와 브라우저의 저장소 한도에 따라 다릅니다.

### 검증용 실제 IFC 형식 예제

`public/examples/authored-building.ifc`와 `authored-building-data.csv`는 직접 작성한 IFC4·업무 데이터 예제입니다. 공식 엔진으로 원형 기둥 등 실제 형상을 읽으며, 두 개 층·5개 부재·Pset/Qset·밀리미터 원본 단위를 포함합니다. Revit에서 내보낸 실제 현장 파일은 아니며 범용 IFC 호환성을 보장하는 자료도 아닙니다. 브라우저에서 IFC 예제를 올린 뒤 CSV를 GlobalId로 연결해 흐름을 확인할 수 있습니다.

IFC 엔진은 사이트 안의 `ifc/`에서 제공하고 추가 CDN·API 키를 요구하지 않습니다. 패키지와 엔진 라이선스·출처는 `public/THIRD_PARTY.md`와 `ifc/LICENSE.md`에 있습니다.

## 구현된 기능

- Three.js + React Three Fiber로 구성한 카페와 4개 상품 선택
- 마우스 드래그 회전, 스크롤 확대, 시점 초기화
- 선택한 상품의 정보 카드와 재고 부족 표시
- 최근 7일·30일 집계, Recharts 매출·판매량 차트
- 상품 검색과 상품 표에서 3D 공간으로 이동
- 샘플 CSV 다운로드, 업로드 검증, 업로드 데이터 브라우저 저장, 샘플 초기화
- IFC 프로젝트 저장·다른 이름으로 저장·다시 열기, 독립 실행 HTML 내보내기·가져오기, 이전 `.monospace` 파일 가져오기
- 모바일 레이아웃, 키보드로 선택 가능한 상품 버튼, WebGL 오류 안내

집계 기간은 **데이터의 가장 최근 날짜**를 기준으로 합니다. 판매 기록이 없는 날짜는 0으로 계산합니다. 재고는 기간별 합계가 아니라 업로드 파일에 기록한 현재 수량입니다. 매출은 `단가 × 판매 수량`이며, 주문 수·환불·할인·가격 변경 이력은 아직 모델링하지 않습니다.

## 실제 데이터 업로드

화면의 **샘플 CSV**를 내려받고 수정한 다음 **데이터 업로드**에서 선택하세요. 엑셀 파일은 **CSV UTF-8**로 저장해야 합니다. `.xlsx` 직접 업로드는 지원하지 않습니다.

| CSV 열         | 설명                                 | 예시         |
| -------------- | ------------------------------------ | ------------ |
| `product_id`   | 3D 객체와 연결할 상품 코드           | `P001`       |
| `product_name` | 상품명                               | `아메리카노` |
| `category`     | 분류                                 | `커피`       |
| `unit_price`   | 단가, 쉼표 없는 숫자                 | `4500`       |
| `stock`        | 현재 재고, 0 이상의 정수             | `128`        |
| `date`         | 판매일, YYYY-MM-DD                   | `2026-11-04` |
| `quantity`     | 해당 날짜의 판매 수량, 0 이상의 정수 | `60`         |

한 행은 상품 하나의 하루 판매 기록입니다. 상품 코드와 날짜 조합은 중복될 수 없습니다. 같은 상품의 이름·분류·단가·현재 재고는 모든 행에서 동일해야 합니다. 열 순서는 바꿀 수 있지만 위 7개 열이 모두 필요합니다. 최대 파일 크기는 2MB이고, 데이터는 최대 40,000행입니다.

현재 3D 공간은 `P001` 커피, `P002` 라테, `P003` 크루아상, `P004` 케이크 모형으로 구성됩니다. **네 코드를 모두 포함한 파일**을 업로드해야 하며, 이름을 바꾸어도 모형의 외형은 그대로입니다. 임의 개수의 상품과 모델 연결은 이후 확장할 수 있습니다.

업로드 파일은 서버로 전송하지 않고 `localStorage`에 저장합니다. 같은 브라우저에서 새로고침해도 유지되고, **샘플로 초기화**하면 제거됩니다. 저장소가 차단되거나 용량이 부족하면 이번 방문에만 적용하고 안내합니다. 다른 기기와의 공유·동기화는 없습니다.

## 구조와 확장

```text
src/
  App.tsx                    # 대시보드, 업로드와 화면 상태
  components/CafeScene.tsx    # 3D 카페, 상품 ID와 모형 위치 연결
  components/BuildingDashboard.tsx # 건물 샘플 화면과 필터 상태
  components/BuildingScene.tsx # 선택 가능한 건물 구조 부재
  data/sample.ts             # 초기 샘플 데이터
  data/building.ts           # 가상 건물 형상과 부재 속성
  lib/data.ts                # CSV 검증과 순수 집계 함수
  lib/building.ts            # 층 필터와 부재 물량 집계
  lib/data.test.ts            # 데이터 계층 테스트
  projects/                  # 프로젝트 형식 검증, IndexedDB 저장, 파일 내보내기·가져오기
  types.ts                   # Product / DailySale 계약
  styles.css                 # 반응형 스타일
public/sample-products.csv   # 업로드 템플릿
e2e/                       # 브라우저 기능 테스트
```

카페 데이터 계약은 `Product { id, name, category, unitPrice, stock, sales: [{date, quantity}] }`입니다. 이후 API 응답을 이 구조로 변환해 상태에 넣으면 기존 카드와 차트를 활용할 수 있습니다. 실제 IFC의 계약은 `src/ifc/types.ts`, 업무 표와 연결 진단은 `src/business/types.ts`, 저장 프로젝트 형식은 `src/projects/types.ts`에 있습니다. 실제 외부 API·서버 DB, 사용자 인증, GLB/glTF 파일 가져오기는 아직 구현하지 않았습니다.

## 검증

```bash
npm run typecheck
npm test
npm run build
npm run test:e2e
```

브라우저 테스트는 시스템 Chromium(`/usr/bin/chromium`)을 사용합니다. 다른 위치에 설치했다면 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`로 지정하세요. 예: macOS에서는 설치된 Chrome 실행 파일 경로를 지정합니다. 개발 서버가 없으면 테스트 설정이 자동 실행합니다. 테스트는 샘플/기간 집계, CSV 교체·오류·새로고침 보존, 상품 선택·검색, IFC 프로젝트 저장·다시 열기·HTML 파일 왕복·오프라인 열기와 재내보내기·실패 시 기존 상태 보존, 모바일 화면을 검증합니다.

3D에는 WebGL을 지원하는 브라우저가 필요합니다. IFC는 WebAssembly와 Worker를 사용할 수 있는 최신 Chrome·Edge를 권장합니다. 기본 샘플은 업로드 없이 동작하고, 실제 파일 처리도 API 키 없이 브라우저에서 수행합니다.
