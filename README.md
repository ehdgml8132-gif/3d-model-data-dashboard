# Monospace · 3D 모형 데이터 대시보드

3층 건물 샘플과 실제 IFC 모델에서 부재 속성, 층별 물량, 연결한 업무 데이터를 살펴보는 React 웹 앱입니다. IFC와 엑셀·CSV는 브라우저에서 처리합니다.

## 실행

Node.js 24 LTS와 npm을 사용합니다. 이 저장소의 기존 체크아웃에서 실행하세요.

```bash
npm ci
npm run dev
```

개발 서버 기본 포트는 `5173`입니다. 프로덕션 빌드는 `npm run build`, 빌드 결과 로컬 확인은 `npm run preview`입니다.

## 웹사이트 배포

이 앱은 별도 서버나 서버 DB 없이 정적 웹사이트로 게시할 수 있습니다. 프로젝트는 사용 중인 브라우저의 IndexedDB에 저장합니다. 빌드의 상대 경로를 사용하므로 도메인 루트와 GitHub Pages의 저장소 하위 경로에서 모두 사용할 수 있습니다.

GitHub Pages 자동 배포 설정은 `.github/workflows/deploy-pages.yml`에 있습니다. GitHub 저장소 **Settings → Pages → Build and deployment → Source**에서 **GitHub Actions**를 선택하면, `main`에 코드를 올리거나 **Actions → Deploy Monospace website → Run workflow**로 빌드·배포할 수 있습니다. 워크플로가 표시하는 실제 배포 URL을 확인하세요. 로컬 설정 파일이 추가된 것만으로 원격 사이트가 게시되지는 않습니다.

정적 호스팅에 직접 업로드할 ZIP은 다음 명령으로 생성합니다.

```bash
npm run build:site
```

`dist/monospace-website.zip`을 풀면 `index.html`, `assets/`, `ifc/`, `examples/`, `favicon.svg`, `THIRD_PARTY.md`와 HTML 내보내기용 `monospace-building-preview.html`이 들어 있습니다. IFC 엔진이 들어 있는 **`ifc/` 폴더를 포함해 전체 내용**을 정적 호스팅의 게시 폴더에 올리세요. 빌드 명령은 `npm run build`, 게시 폴더는 `dist`입니다. Node.js 서버를 계속 실행할 필요는 없습니다.

ZIP 생성 명령에는 Python 3가 필요합니다. 일반 웹사이트 빌드와 GitHub Pages 배포에는 Python을 직접 실행하지 않습니다.

사이트를 열면 기본 3층 건물 샘플의 공간 데이터 화면이 표시됩니다.

### 서버 없이 화면 열기

이 클라우드 채팅에서는 실행 중인 개발 서버가 자동으로 웹 미리보기로 표시되지 않습니다. 별도의 호스팅 없이 화면을 확인하려면 다음 명령으로 단일 HTML 파일을 만들 수 있습니다.

```bash
npm run build:standalone
```

생성된 `dist/monospace-preview.html`을 내려받아 Chrome·Edge 등 WebGL 지원 브라우저에서 여세요. 파일에 뷰어와 IFC 처리 엔진이 포함되어 있어 오프라인에서도 3층 샘플과 IFC 모델을 볼 수 있습니다. 프로젝트 HTML 내보내기에 쓰이는 `dist/monospace-building-preview.html`도 함께 생성됩니다.

## 건물 모델 샘플

기본 화면에는 코드로 만든 **3층 건물의 BIM 예제**가 표시됩니다.

- 전체 또는 특정 층의 기둥·보·슬래브·벽 표시
- 3D 부재 또는 목록 선택 시 부재명·분류·층·재료·규격·체적 표시
- 층·부재 종류·검색 조건에 맞는 목록과 물량 집계
- 화면 회전·확대 및 시점 초기화

사이드바의 **공간·부재 정보**를 누르면 현재 모델의 공간 화면으로 돌아갑니다. **공간 데이터**에서 3D 모델·선택한 부재 속성과 층별 물량을 보고, **부재 데이터**에서 전체 목록을 검색·필터링하며 재료·IFC 분류·규격·체적을 비교할 수 있습니다. 데이터 목록의 부재를 선택하면 공간 화면으로 이동해 같은 부재를 강조합니다.

층 선택은 두 화면에서 공유합니다. 부재 데이터 화면의 검색어·종류 필터는 그 화면에만 적용되며, 공간 화면의 모델을 숨기지 않습니다. 화면을 오갈 때 검색 조건과 선택한 부재가 유지됩니다.

### 카드 필터

뷰어 위 요약 카드 네 개의 우측 상단 아이콘을 누르면 필터가 열립니다. **표시 부재**는 부재 종류나 개별 부재, **총 체적**은 m³ 범위와 체적 미확인 포함 여부, **표시 층**과 **재료 종류·표기**는 여러 층이나 재료를 체크해 선택할 수 있습니다. 같은 항목에서 고른 값은 함께 포함하고, 서로 다른 카드의 조건은 모두 만족하는 부재만 표시합니다. 부재 종류와 개별 부재를 함께 지정하면 두 조건을 모두 적용합니다.

IFC 모델을 불러온 뒤에는 중복되는 상단 층 버튼을 표시하지 않으며, **표시 층** 카드의 필터로 층을 선택합니다. 기본 건물 샘플에서는 기존 층 버튼도 사용할 수 있습니다.

카드 필터는 3D 모델·부재 목록·요약 지표·그래프에 함께 적용됩니다. 필터에 가려진 부재의 선택은 해제되며, 조건에 맞는 부재가 없어도 필터의 전체 선택지는 유지됩니다. 각 팝업의 **이 필터 초기화**로 해당 조건을 복원하거나 **전체 필터 초기화**로 모든 조건을 해제할 수 있습니다. 체적 범위는 양 끝 값을 포함하며, 알 수 없는 체적을 0으로 간주하지 않습니다. 목록 체크는 바로 반영되고 체적 범위는 **적용**을 눌러 반영합니다.

**총 체적** 필터 창의 **체적 미확인 사유**는 현재 카드에 집계된 부재를 기준으로 실제 판독 사유와 부재 수를 표시합니다. Pset 체적 속성 없음, 빈 값·해석할 수 없는 값, 확인할 수 없거나 불일치하는 단위, 체적 값 충돌, 속성 읽기 실패·탐색 한도를 구분하며 **미확인 부재 보기**에서 부재명·ID·층과 기록된 속성·값·단위를 확인할 수 있습니다. 목록은 20개씩 표시하며 0 m³는 미확인에 포함하지 않습니다. 체적 조건을 수정 중인 경우에는 **적용** 후 집계가 바뀌며, Qto/BaseQuantities를 대체 체적으로 사용하지 않습니다. 프로젝트나 HTML을 다시 열면 IFC 원본에서 사유를 다시 판독합니다.

필터는 같은 작업 공간에서 화면을 오갈 때 유지됩니다. 새 IFC 모델을 성공적으로 불러오거나 샘플로 돌아가면 초기화되며, 가져오기를 취소하거나 실패하면 기존 조건을 유지합니다. 단면상자는 화면만 잘라 표시하므로 카드 필터의 집계 값을 다시 계산하지 않습니다.

### 선택 해제·단면상자와 그래프

- 처음 건물 화면을 열거나 새 IFC 모델을 불러오거나 샘플로 돌아오면 **객체가 선택되지 않은 상태**로 시작합니다. 이후 직접 선택한 부재는 같은 작업 공간의 화면을 오갈 때 유지됩니다.
- 뷰어의 **빈 곳을 클릭하거나 Esc·선택 해제**를 누르면 부재 강조와 상세 선택을 해제합니다. 단면상자의 화살표도 함께 숨기며 잘린 범위는 유지합니다. 화면이나 층을 바꿔도 다른 부재를 자동으로 선택하지 않으며, 모델이나 목록에서 부재를 다시 선택할 수 있습니다.
- 뷰어 우측 상단 시점 초기화 버튼 옆의 **단면상자**를 켜면 먼저 상자의 윤곽선만 표시됩니다. **윤곽선을 클릭하거나 터치해 상자를 선택하면** 여섯 면을 조절하는 화살표가 나타납니다. 부재가 선택되어 있으면 그 부재를 감싸는 범위로, 선택이 없으면 전체 건물을 포함하는 범위로 시작합니다. 기준은 켜는 순간 정해지므로 이후 다른 부재를 선택하거나 선택을 해제해도 바뀌지 않습니다. 다른 부재나 전체 건물을 기준으로 다시 만들려면 체크를 껐다 켜세요.
- 선택한 단면상자의 **수평 회전** 바를 움직여 건물의 방향에 맞춰 각도를 −180°부터 180°까지 조절할 수 있습니다. **단면 회전 초기화**를 누르면 0°로 돌아갑니다. IFC 프로젝트를 저장하면 단면상자의 각도도 보관됩니다.
- 선택한 단면상자의 **화살표를 직접 드래그**해 좌우·상하·앞뒤 범위를 조절합니다. 화살표를 움직이는 동안에는 화면 회전이 잠시 멈추고, 놓으면 다시 회전할 수 있습니다. 다른 부재를 클릭하면 그 부재를 선택하고 단면상자의 화살표를 숨깁니다. 빈 곳을 클릭하거나 **Esc·선택 해제**를 누르면 객체와 상자 선택을 모두 해제하며 잘린 범위는 유지합니다. 뷰어 상단의 **단면 범위 초기화**는 현재 기준 상자의 여섯 면을 원래 위치로 복원하며, 단면상자 체크를 끄면 전체 형상을 다시 표시합니다. 아래쪽 X·Y·Z 슬라이더는 제공하지 않습니다. 잘린 바깥쪽 부재는 뷰어에서 클릭되지 않습니다.
- 뷰어 아래 **층별 체적/부재 수**와 **부재 종류 구성** 그래프는 현재 층 필터의 데이터를 보여줍니다. 단면상자는 표시만 자르므로 표·그래프의 부재 개수와 체적을 재계산하지 않습니다. IFC 체적은 계속 Pset의 `체적`/`Volume` 값을 사용하며, 체적이 없는 부재는 0으로 확정하지 않고 미확인 수를 표시합니다. 층별 그래프의 수치는 **층별 수치 보기**에서도 확인할 수 있습니다.

기본 3층 샘플은 Revit에서 내보낸 파일을 읽은 결과가 아닙니다. `IfcColumn` 등의 분류와 `DEMO-`로 시작하는 ID는 데이터 연결 방식을 보여주기 위한 가상 값입니다. 샘플 체적은 직육면체 형상의 단순 합계이며, 부재 접합부 중복을 차감하지 않습니다. **IFC 모델 업로드**로 실제 모델을 열면 새 프로젝트로 저장됩니다. **샘플로 돌아가기**를 눌러 기본 3층 모델을 다시 보고, **프로젝트 열기**에서 저장한 IFC를 열 수 있습니다.

## 실제 IFC 모델과 업무 데이터 연결

1. **IFC 모델 업로드**에서 Revit 등에서 내보낸 `.ifc`를 선택합니다.
2. 가져오기가 끝나면 실제 삼각형 형상이 표시됩니다. 부재를 누르면 GlobalId·Tag·IFC 분류·층·재료와 지원되는 속성집합(Pset), 수량집합(Qset), 유형 속성을 확인할 수 있습니다.
3. **공간 데이터 / 부재 데이터**에서 층과 종류를 선택하고 실제 부재 목록을 검색합니다. IFC의 층 이름을 그대로 사용하며, 층 관계가 없는 부재는 미지정으로 표시합니다.
4. **업무 데이터 연결**에서 `.csv` 또는 `.xlsx`를 선택합니다. 엑셀은 읽을 시트를 선택하세요. 각 시트의 첫 번째 비어 있지 않은 행을 열 이름으로 사용합니다.
5. 모델 연결 키 **GlobalId / Tag / 부재 ID**와 데이터의 대응 열을 지정합니다. 연결 가능·미연결·중복 진단을 확인하고 **데이터 연결**을 누릅니다.
6. 부재를 클릭하면 연결된 공사비·진행 상태·담당자 등 파일에 들어 있는 열을 속성 카드에서 확인할 수 있습니다. **업무 데이터 연결 해제**는 모델을 유지한 채 표 연결만 제거합니다.

연결키는 앞뒤 공백을 제거한 **문자열의 정확한 값**으로 비교합니다. 대소문자와 선행 0을 구분합니다. 엑셀 ID 열은 텍스트로 저장하는 것을 권장합니다. GlobalId는 내보낸 IFC의 값을 사용하고, 내부 번호 기반 `IFC-번호`는 개정 모델 간 고정 식별자로 간주하지 마세요. 같은 키에 여러 행·부재가 있으면 모호한 후보를 표시하며 임의의 첫 행을 연결하거나 물량을 합산하지 않습니다.

연결된 값을 표시하는 기능으로, 임의 업무 열의 집계 차트·공사비 계산·공정 자동 판정은 아직 제공하지 않습니다. XLSX 수식은 실행하지 않고 저장된 계산 결과만 읽습니다. 결과가 없는 수식은 빈 값으로 표시합니다.

### 모델 수량·단위와 처리 한도

- IFC 형상은 공식 **web-ifc 0.0.78** 엔진으로 해석하고 실제 배치 행렬을 적용합니다. 원본 길이 단위와 뷰어의 미터 좌표를 구분합니다.
- 체적은 속성집합(Pset)의 단일 속성인 **`체적`(Revit) 또는 `Volume`**에서 읽습니다. 속성의 명시적 단위, 프로젝트의 체적 단위 또는 값에 표시된 지원 단위 접미사를 사용해 m³로 정규화합니다. **속성값이나 단위를 알 수 없으면 `—`**로 표시합니다. Qto/BaseQuantities·형상·경계상자 값으로 대체하지 않습니다. 합계에는 변환된 체적만 포함하고 누락 수를 안내합니다. Qset은 부재의 일반 속성 조회에서 계속 확인할 수 있습니다.
- 일부 속성·단위를 지원하지 못하면 가져오기 안내를 확인하세요. 속성 조회·체적 속성 표시는 설계 검증이나 정밀 물량 산출을 대체하지 않습니다.
- IFC: 최대 **150MB**, 부재 50,000개, 배치 메시 100,000개, 복사한 형상 버퍼 240MB. 한도를 넘으면 모델을 분할해 내보내세요. 모델 복잡도와 기기 메모리에 따라 더 작은 파일에서도 한도가 적용될 수 있습니다.
- 업무 CSV/XLSX: 최대 **10MB**, 시트 30개, 시트당 데이터 30,000행·200열·1,000,000셀. XLSX는 압축 해제 항목·전체 크기도 검사합니다. `.xls`, `.xlsm`, 암호화 파일은 지원하지 않습니다. CSV는 UTF-8로 저장하세요.

불러오기는 별도 작업자에서 수행하며 취소할 수 있습니다. 가져오기에 실패하거나 취소하면 기존 모델·업무 연결을 유지합니다. **새 모델을 성공적으로 불러오면 이전 업무 연결은 해제**하므로 새 모델의 키에 맞게 다시 연결하세요.

IFC 업로드가 완료되면 원본 IFC와 처음 열린 화면이 브라우저에 자동 저장됩니다. 이후 업무 표 연결과 화면 설정을 보관하려면 **프로젝트 저장**을 누르세요.

### 프로젝트 저장·다른 이름으로 저장

1. IFC 모델을 업로드하면 파일 이름에서 `.ifc`를 뺀 이름으로 새 프로젝트를 만듭니다. 같은 이름의 IFC를 다시 올려도 별도 저장본이 생깁니다.
2. 이후 **프로젝트 저장**은 현재 저장본을 갱신합니다. **다른 이름으로 저장**은 새 프로젝트를 만들므로 이전 저장본을 유지하면서 현장·작업별 사본을 만들 수 있습니다. 같은 이름을 입력해도 다른 이름으로 저장은 기존 항목을 덮어쓰지 않습니다.
3. **프로젝트 열기**에서 **기본 건물 샘플**이나 브라우저에 저장한 IFC 프로젝트를 고릅니다. 기본 샘플을 열면 3층 사무동의 초기 공간 화면이 표시됩니다. IFC 프로젝트를 열면 원본 IFC를 다시 해석하고 업무 표를 연결한 뒤 공간/부재 화면, 카드 필터, 검색·종류 조건, 선택한 부재, 단면상자, 시점을 복원합니다. 열기에 실패하거나 취소하면 현재 모델과 화면은 유지합니다.
4. **파일로 내보내기**는 원본 IFC와 업무 표·화면 설정, 뷰어를 포함하는 **`.html` 파일**을 내려받습니다. 파일을 Chrome·Edge 등에서 직접 열면 저장한 프로젝트가 복원되며, 인터넷 연결이나 별도 서버 없이 모델·데이터를 살펴볼 수 있습니다. 다른 기기로 전달할 때도 HTML 파일 하나만 복사하면 됩니다. 내보낸 HTML에는 프로젝트 이름·저장 상태와 저장·다른 이름 저장·열기·내보내기 버튼이 있는 프로젝트 관리 영역을 표시하지 않습니다. 모델 선택과 필터·단면상자 등 뷰어 기능은 계속 사용할 수 있습니다.
5. 사이트의 **프로젝트 열기 → 프로젝트 파일 열기**에서도 내보낸 HTML을 가져올 수 있습니다. 이전 `.monospace` 파일도 계속 읽을 수 있습니다. 파일을 연 것만으로 브라우저 저장 목록에 추가되지는 않으므로 계속 보관하려면 **프로젝트 저장**을 누릅니다.

브라우저 저장본은 같은 사이트 주소·같은 브라우저에서 열 수 있습니다. 브라우저 데이터 삭제나 비공개 모드 종료로 사라질 수 있으므로 보관·전달할 자료는 프로젝트 파일로도 내보내세요. 저장소가 차단되거나 용량이 부족하면 오류를 표시합니다. 이미 열어 둔 모델과 기존 저장본을 이용할 수 있고, 파일 내보내기도 계속 사용할 수 있습니다.

프로젝트는 원본 IFC 최대 **150MB**, 설정과 업무 표를 담는 프로젝트 메타데이터 최대 **64MB**를 지원합니다. HTML에는 뷰어와 IFC 처리 엔진도 포함되므로 원본 IFC보다 파일이 커집니다. 브라우저에 저장할 수 있는 전체 용량은 기기와 브라우저의 저장소 한도에 따라 다릅니다.

### 검증용 실제 IFC 형식 예제

`public/examples/authored-building.ifc`와 `authored-building-data.csv`는 직접 작성한 IFC4·업무 데이터 예제입니다. 공식 엔진으로 원형 기둥 등 실제 형상을 읽으며, 두 개 층·5개 부재·Pset/Qset·밀리미터 원본 단위를 포함합니다. Revit에서 내보낸 실제 현장 파일은 아니며 범용 IFC 호환성을 보장하는 자료도 아닙니다. 브라우저에서 IFC 예제를 올린 뒤 CSV를 GlobalId로 연결해 흐름을 확인할 수 있습니다.

IFC 엔진은 사이트 안의 `ifc/`에서 제공하고 추가 CDN·API 키를 요구하지 않습니다. 패키지와 엔진 라이선스·출처는 `public/THIRD_PARTY.md`와 `ifc/LICENSE.md`에 있습니다.

## 구조

```text
src/
  main.tsx                         # 대시보드 진입점
  components/BuildingDashboard.tsx # 건물·IFC 작업 공간
  components/BuildingScene.tsx     # 기본 3층 모델
  components/IfcScene.tsx          # IFC 모델 뷰어
  data/building.ts                 # 3층 건물 형상과 부재 속성
  ifc/                             # IFC 해석과 데이터 형식
  business/                        # 업무 표와 연결 진단 형식
  projects/                        # 브라우저 저장, 파일 내보내기·가져오기
public/examples/                   # IFC·업무 데이터 예제
e2e/                               # 브라우저 기능 테스트
```

## 검증

```bash
npm run typecheck
npm test
npm run build
npm run test:e2e
```

브라우저 테스트는 시스템 Chromium(`/usr/bin/chromium`)을 사용합니다. 다른 위치에 설치했다면 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`로 지정하세요. 예: macOS에서는 설치된 Chrome 실행 파일 경로를 지정합니다. 개발 서버가 없으면 테스트 설정이 자동 실행합니다. 테스트는 건물 샘플의 WebGL 화면, 부재 선택·필터·단면상자, IFC 가져오기와 업무 데이터 연결, 프로젝트 저장·다시 열기, HTML 내보내기·오프라인 열기, 실패 시 기존 상태 보존, 모바일 화면을 검증합니다.

3D에는 WebGL을 지원하는 브라우저가 필요합니다. IFC는 WebAssembly와 Worker를 사용할 수 있는 최신 Chrome·Edge를 권장합니다. 기본 샘플은 업로드 없이 동작하고, 실제 파일 처리도 API 키 없이 브라우저에서 수행합니다.
