# Monospace · 3D 모형 데이터 대시보드

3D 공간의 객체를 클릭해 관련 데이터를 살펴보는 React 웹 앱입니다. **카페 판매 대시보드**와 **3층 건물 부재 대시보드** 두 가지 샘플을 제공합니다. 카페의 초기 데이터는 가상의 4개 상품과 30일 판매 기록이며, CSV 업로드로 교체할 수 있습니다.

## 실행

Node.js 24 LTS와 npm을 사용합니다. 이 저장소의 기존 체크아웃에서 실행하세요.

```bash
npm ci
npm run dev
```

개발 서버 기본 포트는 `5173`입니다. 프로덕션 빌드는 `npm run build`, 빌드 결과 로컬 확인은 `npm run preview`입니다.

## 웹사이트 배포

이 앱은 별도 서버나 DB 없이 정적 웹사이트로 게시할 수 있습니다. 카페와 건물, 공간·부재 데이터 화면이 하나의 사이트에 포함됩니다. 빌드의 상대 경로를 사용하므로 도메인 루트와 GitHub Pages의 저장소 하위 경로에서 모두 사용할 수 있습니다.

GitHub Pages 자동 배포 설정은 `.github/workflows/deploy-pages.yml`에 있습니다. GitHub 저장소 **Settings → Pages → Build and deployment → Source**에서 **GitHub Actions**를 선택하면, `main`에 코드를 올리거나 **Actions → Deploy Monospace website → Run workflow**로 빌드·배포할 수 있습니다. 워크플로가 표시하는 실제 배포 URL을 확인하세요. 로컬 설정 파일이 추가된 것만으로 원격 사이트가 게시되지는 않습니다.

정적 호스팅에 직접 업로드할 ZIP은 다음 명령으로 생성합니다.

```bash
npm run build:site
```

`dist/monospace-website.zip`을 풀면 `index.html`, `assets/`, `favicon.svg`, `sample-products.csv`가 들어 있습니다. 압축을 푼 내용 전체를 정적 호스팅의 게시 폴더에 올리세요. 빌드 명령은 `npm run build`, 게시 폴더는 `dist`입니다. Node.js 서버를 계속 실행할 필요는 없습니다.

ZIP 생성 명령에는 Python 3가 필요합니다. 일반 웹사이트 빌드와 GitHub Pages 배포에는 Python을 직접 실행하지 않습니다.

사이트 첫 화면은 카페입니다. 같은 사이트 주소 뒤에 `?sample=building`을 붙이면 건물 샘플로 시작합니다. 업로드한 카페 CSV는 사용 중인 브라우저에만 저장되며 사이트 방문자 사이에서 공유되지 않습니다.

### 서버 없이 화면 열기

이 클라우드 채팅에서는 실행 중인 개발 서버가 자동으로 웹 미리보기로 표시되지 않습니다. 별도의 호스팅 없이 화면을 확인하려면 다음 명령으로 단일 HTML 파일을 만들 수 있습니다.

```bash
npm run build:standalone
```

생성된 `dist/monospace-preview.html`을 내려받아 Chrome·Edge 등 WebGL 지원 브라우저에서 여세요. 파일 안에 JavaScript·스타일·샘플 CSV가 포함되어 있어 서버나 패키지 설치 없이 3D 상품 선택, 차트, CSV 업로드를 사용할 수 있습니다. 이 파일은 오프라인 확인용이며 공개 웹 주소를 생성하거나 배포하지 않습니다. 코드 변경 후에는 다시 생성해야 합니다.

건물 샘플로 바로 시작하는 `dist/monospace-building-preview.html`도 함께 생성합니다. 두 파일 모두 사이드바의 **카페 샘플 / 건물 샘플** 버튼으로 예제를 바꿀 수 있습니다. 기존 카페에서 업로드한 데이터는 샘플을 전환해도 유지됩니다.

## 건물 모델 샘플

기존 카페와 별도로, 코드로 만든 **3층 건물의 BIM 예제**를 제공합니다. 사이드바에서 **건물 샘플**을 누르거나 개발 서버의 `?sample=building`으로 진입할 수 있습니다.

- 전체 또는 특정 층의 기둥·보·슬래브·벽 표시
- 3D 부재 또는 목록 선택 시 부재명·분류·층·재료·규격·체적 표시
- 층·부재 종류·검색 조건에 맞는 목록과 물량 집계
- 화면 회전·확대 및 시점 초기화

건물 메뉴는 **공간 데이터**와 **부재 데이터**로 나뉩니다. 공간 데이터에서 3D 모델·선택한 부재 속성과 층별 물량을 보고, 부재 데이터에서 전체 목록을 검색·필터링하며 재료·IFC 분류·규격·체적을 비교할 수 있습니다. 데이터 목록의 부재를 선택하면 공간 화면으로 이동해 같은 부재를 강조합니다.

층 선택은 두 화면에서 공유합니다. 부재 데이터 화면의 검색어·종류 필터는 그 화면에만 적용되며, 공간 화면의 모델을 숨기지 않습니다. 화면을 오갈 때 검색 조건과 선택한 부재가 유지됩니다.

이 모델은 Revit에서 내보낸 파일을 읽은 결과가 아닙니다. `IfcColumn` 등의 분류와 `DEMO-`로 시작하는 ID는 데이터 연결 방식을 보여주기 위한 가상 값입니다. 표시 체적은 직육면체 형상의 단순 합계이며, 부재 접합부 중복을 차감하지 않습니다. **실제 IFC 업로드는 아직 지원하지 않습니다.**

## 구현된 기능

- Three.js + React Three Fiber로 구성한 카페와 4개 상품 선택
- 마우스 드래그 회전, 스크롤 확대, 시점 초기화
- 선택한 상품의 정보 카드와 재고 부족 표시
- 최근 7일·30일 집계, Recharts 매출·판매량 차트
- 상품 검색과 상품 표에서 3D 공간으로 이동
- 샘플 CSV 다운로드, 업로드 검증, 업로드 데이터 브라우저 저장, 샘플 초기화
- 모바일 레이아웃, 키보드로 선택 가능한 상품 버튼, WebGL 오류 안내

집계 기간은 **데이터의 가장 최근 날짜**를 기준으로 합니다. 판매 기록이 없는 날짜는 0으로 계산합니다. 재고는 기간별 합계가 아니라 업로드 파일에 기록한 현재 수량입니다. 매출은 `단가 × 판매 수량`이며, 주문 수·환불·할인·가격 변경 이력은 아직 모델링하지 않습니다.

## 실제 데이터 업로드

화면의 **샘플 CSV**를 내려받고 수정한 다음 **데이터 업로드**에서 선택하세요. 엑셀 파일은 **CSV UTF-8**로 저장해야 합니다. `.xlsx` 직접 업로드는 지원하지 않습니다.

| CSV 열         | 설명                                 | 예시         |
| -------------- | ------------------------------------ | ------------ |
| `product_id`   | 3D 객체와 연결할 상품 코드           | `P001`       |
| `product_name` | 상품명                               | `아메리카노` |
| `category`     | 분류                                 | `커피`       |
| `unit_price`   | 단가, 쉼표 없는 숫자                 | `4500`       |
| `stock`        | 현재 재고, 0 이상의 정수             | `128`        |
| `date`         | 판매일, YYYY-MM-DD                   | `2026-11-04` |
| `quantity`     | 해당 날짜의 판매 수량, 0 이상의 정수 | `60`         |

한 행은 상품 하나의 하루 판매 기록입니다. 상품 코드와 날짜 조합은 중복될 수 없습니다. 같은 상품의 이름·분류·단가·현재 재고는 모든 행에서 동일해야 합니다. 열 순서는 바꿀 수 있지만 위 7개 열이 모두 필요합니다. 최대 파일 크기는 2MB이고, 데이터는 최대 40,000행입니다.

현재 3D 공간은 `P001` 커피, `P002` 라테, `P003` 크루아상, `P004` 케이크 모형으로 구성됩니다. **네 코드를 모두 포함한 파일**을 업로드해야 하며, 이름을 바꾸어도 모형의 외형은 그대로입니다. 임의 개수의 상품과 모델 연결은 이후 확장할 수 있습니다.

업로드 파일은 서버로 전송하지 않고 `localStorage`에 저장합니다. 같은 브라우저에서 새로고침해도 유지되고, **샘플로 초기화**하면 제거됩니다. 저장소가 차단되거나 용량이 부족하면 이번 방문에만 적용하고 안내합니다. 다른 기기와의 공유·동기화는 없습니다.

## 구조와 확장

```text
src/
  App.tsx                    # 대시보드, 업로드와 화면 상태
  components/CafeScene.tsx    # 3D 카페, 상품 ID와 모형 위치 연결
  components/BuildingDashboard.tsx # 건물 샘플 화면과 필터 상태
  components/BuildingScene.tsx # 선택 가능한 건물 구조 부재
  data/sample.ts             # 초기 샘플 데이터
  data/building.ts           # 가상 건물 형상과 부재 속성
  lib/data.ts                # CSV 검증과 순수 집계 함수
  lib/building.ts            # 층 필터와 부재 물량 집계
  lib/data.test.ts            # 데이터 계층 테스트
  types.ts                   # Product / DailySale 계약
  styles.css                 # 반응형 스타일
public/sample-products.csv   # 업로드 템플릿
e2e/                       # 브라우저 기능 테스트
```

데이터 계약은 `Product { id, name, category, unitPrice, stock, sales: [{date, quantity}] }`입니다. 이후 API 응답을 이 구조로 변환해 상태에 넣으면 기존 카드와 차트를 활용할 수 있습니다. 실제 외부 API·DB, 사용자 인증, GLB/glTF·IFC 파일 가져오기는 아직 구현하지 않았습니다. 실제 모델은 객체 ID와 상품/부재 ID를 연결하는 매핑이 추가로 필요합니다.

## 검증

```bash
npm run typecheck
npm test
npm run build
npm run test:e2e
```

브라우저 테스트는 시스템 Chromium(`/usr/bin/chromium`)을 사용합니다. 다른 위치에 설치했다면 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`로 지정하세요. 예: macOS에서는 설치된 Chrome 실행 파일 경로를 지정합니다. 개발 서버가 없으면 테스트 설정이 자동 실행합니다. 테스트는 샘플/기간 집계, CSV 교체·오류·새로고침 보존, 상품 선택·검색, 모바일 화면을 검증합니다.

3D에는 WebGL을 지원하는 브라우저가 필요합니다. 외부 3D 모델·이미지·폰트나 API 키 없이 동작합니다.
